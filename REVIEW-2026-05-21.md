## BLOCKERS

### 1. `mcp-http.js` binds MCP server on `0.0.0.0:8081` — no auth, LAN-reachable

**File:** `D:/Yahia/active/qsearch/src/mcp-http.js:19`

```js
const HOST = process.env.MCP_HOST || '0.0.0.0'
```

The MCP-over-HTTP server defaults to all interfaces with zero authentication — no token check, no IP allowlist. CORS is `Access-Control-Allow-Origin: *` (line 29). Any machine on the LAN can call MCP tools: `sweep`, `sweep_context`, `index_research` (arbitrary glob), `web_search`. The log message on line 94 even prints `http://<LAN-IP>:${PORT}` as the intended URL, confirming the design was to share the port — but there is no corresponding auth layer.

**Impact:** a LAN peer can call `index_research` with glob `/**/*` to exfiltrate arbitrary filesystem contents into the Meilisearch corpus, or call `sweep_context` with internal URLs (see finding #3).

**Fix:** default `HOST` to `127.0.0.1`; or add a shared-secret middleware (`Authorization: Bearer <token>`) before routing to any MCP handler.

### 2. `POST /index` accepts arbitrary filesystem glob — no path restriction

**File:** `D:/Yahia/active/qsearch/src/server.js:548–600`

Any path that does not start with `http` is treated as a local file/glob and read unconditionally:

```js
const url = (body.url || body.path || body.glob || '').trim()
if (!url.startsWith('http')) {
  const pattern = url.replace(/\/g, '/')
  const files = await fsGlob(pattern)
  for (const filePath of files) {
    const raw = readFileSync(filePath, 'utf8')   // no path check
    ...
    await meili.index(doc)
```

A caller who reaches `:8080` (REST server, which binds only to localhost per `server.listen(PORT, callback)` — no host argument, so Node defaults to `::` / all interfaces) can POST `{ "glob": "/etc/**/*.conf" }` or `C:/Users/**/*.json` and have the content indexed into Meilisearch where it is searchable. On Windows with Docker this includes the host filesystem mounted inside WSL.

`/ingest/brave` (`src/server.js:705`) has the same issue: `braveDir` is caller-supplied with no canonicalization or path boundary check before being passed to `readdirSync` + `readFileSync`.

**Fix:** resolve the supplied path against a declared allowed root (e.g. process cwd or a configured `QSEARCH_DATA_ROOT`) and reject anything that escapes it. Use `path.resolve()` + `startsWith(allowedRoot)`.

### 3. `POST /sweep_context` is an open SSRF proxy — no internal-IP blocklist

**File:** `D:/Yahia/active/qsearch/src/server.js:1400–1450`, `src/sweep_context.js`, `src/fetch/html.js`

The `urls[]` array is validated only by Zod `z.string().url()` (in the MCP layer) and a length cap of 20. The server-side handler (`handleSweepContext`) passes URLs straight to `fetchHtml`, which calls `fetch(url, { redirect: 'follow' })` with no SSRF guard. No DNS resolution check, no private-range blocklist.

Callers can target:
- `http://169.254.169.254/` (AWS/Azure IMDS — not local here, but relevant if ever cloud-deployed)
- `http://localhost:7700/` (Meilisearch admin — exposes full search index)
- `http://localhost:6333/` (Qdrant REST — vectors + payloads)
- Any Docker network address (`172.17.0.x`)

Because the REST server binds on all interfaces (no explicit `127.0.0.1`), this can be triggered from LAN too once an attacker discovers port 8080.

**Fix:** resolve the URL's hostname before fetching; reject RFC-1918, loopback, link-local, and metadata ranges. A minimal allowlist approach (https-only, public IPs only) is safer.

## WARNINGS

### 4. Meilisearch master key hardcoded as literal `"masterKey"` in docker-compose and server default

**File:** `D:/Yahia/active/qsearch/docker-compose.yml:7`, `src/server.js:58`, `src/obsidian/sync.js:6`

```yaml
MEILI_MASTER_KEY: masterKey
```
```js
const MEILI_KEY = process.env.MEILISEARCH_KEY || 'masterKey'
```

The master key is a well-known default, trivially brute-forced. Meilisearch exposes port `7700` on all Docker interfaces (docker-compose `ports: ["7700:7700"]`). On a machine where Docker uses a host-network bridge accessible from LAN, any host can authenticate to Meilisearch with `masterKey` and dump or delete the entire corpus.

**Fix:** generate a random key (`openssl rand -hex 32`), store it in `.env.local` (already gitignored), and remove the literal default from both docker-compose and JS fallback. Add a startup assertion that refuses to start if the env var is absent or equals `"masterKey"`.

### 5. REST server (`server.js`) listens on all interfaces — no explicit `127.0.0.1` binding

**File:** `D:/Yahia/active/qsearch/src/server.js:1668`

```js
server.listen(PORT, () => { ... })
```

Node's `http.createServer().listen(port, callback)` with no `host` argument binds to `::` (all IPv6 interfaces, including `0.0.0.0` via dual-stack). The startup log says `http://localhost:${PORT}` but the socket is reachable from the LAN. Combined with zero auth on every endpoint, any host on the subnet can call `/sweep`, `/context`, `/cache_store`, `/ingest/brave`, or `/index`.

**Fix:** `server.listen(PORT, '127.0.0.1', callback)`. If LAN access is genuinely needed, add an auth middleware (see finding #1).

## Verdict: BLOCK

Do not expose this service beyond the local loopback until findings #1, #2, and #3 are fixed. Finding #4 is a credential hygiene issue that should be fixed before any multi-user or cloud deployment. Finding #5 is the precondition that makes #2, #3, and #4 exploitable from the network — fix it first as the fastest risk-reduction step (one-line change).

Priority order for a single sitting:
1. `server.listen(PORT, '127.0.0.1', ...)` — closes LAN exposure of all REST endpoints immediately.
2. `mcp-http.js` default `HOST` → `127.0.0.1` or add Bearer auth.
3. SSRF blocklist in `fetchHtml`.
4. Path boundary check in `handleIndex` and `ingestBraveDir`.
5. Rotate Meilisearch master key out of the codebase.
