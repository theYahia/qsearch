# Когда AI-агент ссылается на источник, который его не подтверждает: как часто это происходит и как это проверить

> ЧЕРНОВИК для Habr. Не опубликовано. Все числа взяты дословно из README/leaderboard проекта doesitlie. Перед публикацией — вычитать, проверить теги, оформить под редактор Habr.

## TL;DR

Мы скачали все 273 источника, на которые сослались два фронтир-агента глубокого исследования (Gemini 3.1 Pro Deep Research и Claude Deep Research) по трём юридическим вопросам. Из 199, которые удалось прочитать, **каждый пятый не подтверждал полностью то утверждение, ради которого он был процитирован**. Для каждого вердикта приложена квитанция: само утверждение, фрагмент источника, цитата-доказательство от судьи и ссылка на оригинал. Судья (LLM-as-judge) совпадает с человеческой разметкой на 87.3% (Cohen's κ=0.75 по бинарной шкале). Кеш вердиктов закоммичен в репозиторий, поэтому повторный прогон возвращает ровно те же цифры. Проект называется doesitlie, лицензия кода MIT, данных — CC-BY-4.0.

## Проблема: ссылка есть, а подтверждения нет

Агенты глубокого исследования (Perplexity, ChatGPT, Gemini Deep Research, Exa и другие) отвечают со ссылками. Это выглядит как добросовестность: каждое утверждение подкреплено URL. Но ссылка — это не подтверждение. Измеренные доли ошибочных цитат у разных моделей лежат в диапазоне **от 11% до 95%** (по работам GhostCite, «Cited but Not Verified», CJR). При этом каждый вендор публикует только те числа, которые ему льстят, и нет ни одной публичной таблицы, отвечающей на единственный вопрос, который важен для решения с высокими ставками:

> **Когда инструмент ссылается на источник — действительно ли источник говорит то, что утверждает инструмент?**

Важно сразу разделить два разных провала, потому что их часто валят в кучу:

1. **Сфабрикованная ссылка** — URL ведёт в никуда: 404, мёртвый домен, несуществующая страница. Это легко поймать механически.
2. **Неподтверждающая ссылка** — URL настоящий, страница живая, но источник не говорит того, что приписал ему агент. Это тоньше и интереснее.

Самый неожиданный результат первой версии оказался в пользу агентов: **сфабрикованные URL почти вымерли**. У Gemini — 0 из 154 цитат, у Claude — 2 из 119. Живой режим отказа — второй: ссылка реальна, но источник не подтверждает заявленное полностью.

## Метод: механическая проверка + судья на ранжированных пассажах

Для каждой пары `(утверждение, процитированный_url)`, которую выдал агент, выносится вердикт в два шага.

### Шаг 1 — проверка на фабрикацию (механическая, неоспоримая)

Скачиваем URL. Если 404, отказ DNS или это не настоящая страница → вердикт `Fabricated`. Никакого суждения, никакой модели. Мёртвую или выдуманную ссылку нельзя «заболтать». Если страница достижима, но нечитаема (paywall, блок ботов, PDF не распарсился, таймаут) → это не провал и не зачёт, а **пробел покрытия** (coverage gap), который показывается отдельно, а не прячется в скрытую корзину ошибок.

### Шаг 2 — проверка на подтверждение (LLM-as-judge, аудируемая)

Извлекаем содержимое источника, **детерминированно** ранжируем пассажи, которые касаются конкретики утверждения (лексическое ранжирование: один и тот же вход → одни и те же пассажи), и судья выносит вердикт: `Supported` / `Partial` / `Unsupported`. Точный фрагмент источника и цитата-доказательство от судьи сохраняются рядом с каждым вердиктом, поэтому **любой может перепроверить вручную**.

Принцип консервативен по построению: если подтверждение не выражено явно, вердикт — `Unsupported`. Правдоподобность — не подтверждение.

### Почему судье не нужно доверять

Судья — наименее доверенный компонент конвейера, поэтому он построен так, чтобы доверия не требовать вовсе. На размеченном вручную золотом наборе из 55 цитат он совпадает с человеческими метками:

- **87.3% по бинарной шкале**, Cohen's κ=0.750;
- **83.6% по точной четырёхзначной шкале**, κ=0.737.

κ корректирует на случайные совпадения; значение выше 0.6 считается «существенным» согласием. Для сравнения, опубликованный базовый уровень CiteGuard — 68%. Все расхождения между судьёй и человеком консервативны (судья недооценивает, но никогда не переоценивает) и выложены открыто на вкладке Method. И, поскольку каждый вердикт приезжает со своей квитанцией, судье можно вообще не верить: берёте любую строку и перепроверяете руками.

> Терминологическая точность: κ=0.75 — это согласие **судьи с человеком** (judge↔human), а не согласие нескольких разметчиков между собой и не согласие нескольких судей. Это метрика того, насколько автоматический вердикт совпадает с ручной эталонной разметкой.

## Результат: реальные числа таблицы

Первая версия — юридическая, три темы: неконкуренция (non-compete), квалифицированный иммунитет (qualified immunity), добросовестное использование (fair use). Основные метрики считаются **по всем процитированным URL**, а не только по читаемым — так агент не может надуть свой результат, ссылаясь на источники за paywall или за блоком ботов. Нечитаемая доля (~27%, в основном юридические сайты за Cloudflare) показана как пробел покрытия и не засчитывается ни в одну сторону.

| Агент | Цитат | Покрытие | ✓ Supported | ✗ Unsupported | ☠ Fabricated | Support %¹ |
|---|--:|--:|--:|--:|--:|--:|
| **Gemini 3.1 Pro Deep Research** | 154 | 73.4% | 57.1% | 13.0% | 0.0% | 77.9% |
| **Claude Deep Research** | 119 | 72.3% | 60.5% | 7.6% | 1.7% | 83.7% |

Как читать столбцы:

- **Цитат** — сколько пар `(утверждение, URL)` выдал агент.
- **Покрытие** — доля цитат, которые удалось скачать и осудить (остальное — Error: 403 / paywall / сбой парсинга PDF / таймаут; показывается, а не отбрасывается молча).
- **✓ Supported** — Supported, посчитанный относительно **всех** цитат (пол с поправкой на покрытие).
- **✗ Unsupported** — судья постановил, что источник не подкрепляет утверждение; считается по всем цитатам; **меньше — лучше**.
- **☠ Fabricated** — механически: мёртвый/404/несуществующий URL; **меньше — лучше**.
- **Support %¹** — Supported/прочитанные. Это легаси-метрика, оставлена для преемственности, но она **вторична**, потому что зависит от покрытия.

Таблица ранжируется по Fabricated, затем по Unsupported, затем по Supported с поправкой на покрытие.

Из этой таблицы и берётся заголовочное число. Всего процитировано **273 источника**; прочитать удалось **199** (113 у Gemini + 86 у Claude). Из этих 199 **каждый пятый не подтверждал полностью** заявленное утверждение — это и есть «1 из 5».

### Что НЕ нужно вычитывать из таблицы

Это не рейтинг «кто умнее». Это узкая, конкретная метрика честности цитирования на одном вертикале (право) в первой версии. Здесь нет данных об общем качестве ответов, скорости, цене или о любых других агентах, кроме двух протестированных. Ещё четыре — ChatGPT Deep Research, Perplexity Deep Research, Exa Research и Parallel Search API — числятся в очереди (docketed), но их реальные прогоны пока не проведены, поэтому их строки пусты.

## Почему сначала право

Право — это область, где нечестность цитирования уже стала публичным кризисом с высокими ставками. Суды раз за разом ловят сфабрикованные и неверно процитированные AI-источники: документировано **1200+ судебных дел (2025–2026)**, где юристов санкционировали за сфабрикованные AI-цитаты (Орегон — штраф $109,700; правило Флориды о сфабрикованных цитатах, Rule 2.515(d)(2), вступает в силу 15 июня 2026 года; новые дела появляются еженедельно). При этом прецедентное право полностью публично, поэтому эталонная истина чистая. Широта (другие домены) приходит после того, как метод выдержал проверку.

Технический, финансовый и медицинский вертикали в проекте **зашиты как каркас, но не подделаны**. Скоринг, разбивка по доменам и тест независимости χ² уже сегодня учитывают домен; эти вертикали отображаются как «в очереди» (awaiting real agent runs), а не наполнены выдуманными данными. Как только приземлятся реальные сабмиты по tech/finance/health — подоменные доли и тест «держится ли честность между доменами?» включатся без единой правки кода.

## Почему это воспроизводимо: закоммиченный кеш вердиктов

Главный приём против подкрутки результатов — **открытые данные + открытый код + закоммиченный кеш вердиктов**. Кеш фиксирует каждый вердикт; модель-судья записывается на каждый прогон (потому что хостовые алиасы вроде `deepseek-chat` могут дрейфовать). Повторный прогон возвращает опубликованные числа **точно**.

Дополнительные гарантии:

- **`Fabricated` механический**, а не мнение модели — мёртвую/выдуманную ссылку нельзя оспорить.
- **Основные метрики — по ВСЕМ процитированным URL** (Fabricated, Unsupported), с показанным покрытием — так агент не спрячет слабые цитаты в скрытую корзину Error.
- **Согласие судьи с человеком публикуется через Cohen's κ** (а не только сырым процентом), чтобы число доверия не раздувалось дисбалансом классов.
- **Каждый вердикт приезжает со своим фрагментом источника** в `audit.json` — не согласны? Открываете и проверяете.

Есть отдельный merge-гейт `validate.mjs` (CI-воркфлоу `bench-integrity.yml`). Он заново выводит заголовок («1 из N»), каждую метрику таблицы и κ судья↔человек прямо из `out/all/audit.json` + `gold/labels.json`; подтверждает, что **каждая опубликованная квитанция прослеживается к реальному вердикту** (ничего не выдумано); и проверяет, что `badge.json` согласован. В облачном CI нет локальной модели, поэтому там проверяется детерминизм, а не пере-суждение.

Статистическая строгость вынесена в `bench/stats.js`:

- **Wilson 95% CI** на заголовке — «1 из 5» едет со своей честной планкой погрешности.
- **χ²(вердикт × домен)** — когда приземлятся неюридические прогоны, тест проверит, действительно ли честность цитирования различается по доменам или это шум (с размером эффекта Cramér's V и флагом валидности для малых ожидаемых ячеек).
- **Cohen's κ** для согласия судья↔человек — одна общая реализация в билдере сайта, в инструменте согласия и в тестах; доступны bootstrap-доверительные интервалы (с фиксированным seed → детерминированные).

## Как запустить у себя

Прогон бенчмарка:

```bash
node doesitlie/bench/harness.js <submissions.json> [outdir]
```

Формат `submissions.json`:

```json
[{ "agent": "Perplexity Deep Research",
   "citations": [ { "claim": "…", "url": "https://…" } ] }]
```

На выходе — `leaderboard.md` + `audit.json` (каждый вердикт + фрагмент источника).

Судья: локальная Ollama (`qwen2.5:14b-instruct`, $0) по умолчанию, либо DeepSeek (`DOESITLIE_JUDGE_PROVIDER=deepseek`, ключ `DEEPSEEK_API_KEY` в `.env.local`). Температура 0, метка судьи записывается на каждый прогон. Конвейер построен на подложке верификации из проекта qsearch (fetch с защитой от SSRF + headless-фолбэк через Crawl4AI + извлечение основного содержимого, через `fetch_content.js`).

Перепроверка без необходимости доверять:

```bash
npm test          # статистика, скоринг, разбивка по доменам, κ — всё покрыто юнит-тестами
npm run build     # пересчитать данные сайта (заголовок, κ, badge) из сырого audit — числа нигде не захардкожены
npm run validate  # гейт целостности: каждое опубликованное число обязано пере-выводиться из квитанций, иначе падает
```

Сборка данных сайта из аудита:

```bash
node site/build_site.mjs   # data.json + doesitlie.csv + badge.json + og.html, вшивает заголовок в index.html
```

Живая таблица — на [doesitlie.org](https://doesitlie.org): каждое число на ней открывает свой экспонат — утверждение, фрагмент источника, цитату-доказательство судьи и ссылку на оригинал.

## Не согласны с вердиктом

Квитанция — это и есть форма апелляции. Открываете строку, читаете фрагмент источника и оспариваете вердикт через issue-шаблон в репозитории. Каждый спор публичен, каждое разрешение залогировано. Чтобы выдвинуть следующего агента в очередь — голосуете в issue «request-an-agent».

## Связанные работы

Качество цитирования у агентов глубокого исследования сейчас измеряют в нескольких местах: DRACO (Perplexity) и DeepResearch Bench (USTC) оценивают точность цитирования по общим доменам; Rao, Wong & Callison-Burch измеряют долю сфабрикованных URL в масштабе; LegalCiteBench проверяет полноту цитирования в юридических моделях. Метод-якоря самого бенчмарка: CiteGuard (arXiv:2510.17853), FACTS Grounding (Google DeepMind), NLI-энтейлмент (FEVER), DeepResearch Bench; существование юридических цитат — против CourtListener / Free Law Project (в роадмапе).

doesitlie занимает более узкую, дополняющую нишу: **нейтральная запись** (без денег от вендоров, инструменты мейнтейнера вне таблицы), где каждый вердикт открывает свою **квитанцию** для ручной перепроверки, судья спрашивает, **подтверждает ли источник утверждение** (а не просто резолвится ли URL), а эталонная истина — это публичное прецедентное право, скачанное вживую.
