## 2. The `bench/.cache` decision — commit vs gitignore

**What it is:** the verifier's verdict cache — 972 JSON files (3.4 MB on disk), keyed by
`sha256(CACHE_VERSION|judgeLabel|url|claim)`. Each file is one cached `verifyCitation` result. Its purpose
per `src/verifier/index.js` comments: *"the published benchmark stays byte-reproducible against its
committed verdict cache"* — i.e. anyone can `DOESITLIE_NO_CACHE` unset and re-run `npm run bench` and get
the **exact** published verdicts back **without a judge model and without network**, because every call hits
the cache.

**Key nuance that changes the framing:** the CI integrity gate (`validate.mjs`) does **NOT** read `.cache`.
It re-derives every headline number, board metric, and judge↔human κ from `bench/out/all/audit.json` +
`bench/gold/labels.json` (confirmed by reading `validate.mjs`). So **CI honesty does not depend on the cache
at all.** The cache only matters for the stronger claim: *"re-run the bench yourself and reproduce the
verdicts offline."*

| Option | Pros | Cons |
|---|---|---|
| **Commit `.cache`** (pruned to live `v7` + chosen judge) | Full offline reproducibility of the bench run, not just the audit re-derivation. Strongest "audit me" posture — the project's entire thesis is citation honesty. Small in git (JSON packs well; on-disk 3.4 MB ≈ well under a typical repo budget). | Repo carries 900+ opaque hash-named files; "bloat" perception; cache churns when verifier logic bumps `CACHE_VERSION`. |
| **Gitignore `.cache`** | Clean repo, no hash-file noise. | Breaks the "reproduce offline without a judge" promise — a re-run needs Ollama/DeepSeek + live network and may drift (DeepSeek `deepseek-chat` is an **unpinned** alias per the verifier's own comment → fresh re-judge is NOT byte-reproducible). Reproducibility then rests only on `audit.json` re-derivation. |

**RECOMMENDATION: COMMIT the cache, but PRUNE it first.** Reasoning:

1. The product *is* reproducible citation honesty. A reviewer landing from Show HN / a bar committee being
   able to `git clone && npm run bench` and get byte-identical verdicts **with no API key and no judge** is
   the single most credibility-compounding property. Gitignoring it forfeits that.
2. The size objection is weak: 3.4 MB on disk, and git-packed it is materially smaller (JSON delta-compresses
   well). This is not "repo bloat" by any practical standard.
3. The unpinned-judge problem (`deepseek-chat` alias moves) means a fresh re-judge is explicitly **not**
   byte-reproducible — the committed cache is the *only* mechanism that delivers run-to-run determinism. The
   verifier source says this in its own NOTE. Dropping the cache silently downgrades the reproducibility claim.
4. **Prune before commit** to kill the bloat/noise objection: keep only entries whose key matches the live
   `CACHE_VERSION` (`v7`) and the **published** judge label. 🔴 **The judge is NOT a free "decide ollama vs
   deepseek" choice** (fact-check 2026-06-24): the 273 published rows hit the cache **only** under
   `v7|deepseek:deepseek-chat` (273/273); under `v7|ollama:qwen2.5:14b-instruct` only **90/273** hit. **Pruning
   to v7+ollama would drop 183 of the 273 published verdicts and silently break the "byte-reproducible offline,
   no API key" promise this whole section rests on.** Prune to **`v7` + `deepseek:deepseek-chat`** (973 → ~273).
   Note the tension this exposes: the published judge (DeepSeek) is exactly the **unpinned-alias** judge §2 warns
   against — the committed cache is what makes it reproducible, but a *fresh* re-judge to regenerate the cache is
   non-deterministic. Pruning script (run at publish time, **not now**): rather than `npm run bench` re-judge
   (which needs `DEEPSEEK_API_KEY` and may drift), prune by **reconstructing the 273 keys from the committed
   `audit.json` and keeping only those `.cache/<key>.json` files** — deterministic, no judge call. Then
   `git add bench/.cache`, verify count ≈273, and `validate.mjs` still passes.

**If the user rejects committing it:** gitignore `bench/.cache/`, and downgrade the README reproducibility
claim from "byte-reproducible offline" to "integrity-checked: every published number re-derives from
`audit.json` (run `npm run validate`); a full re-judge requires a local judge." Do not leave a
"byte-reproducible" claim in the README while gitignoring the only artifact that makes it true.

## 4. CI — does `bench-integrity.yml` run offline in cloud CI?

**Yes, the integrity gate runs fully offline in GitHub-hosted runners.** Read of the workflow + `validate.mjs`:

- It runs two steps on `ubuntu-latest` + Node 20: (1) `node --test bench/test/*.test.js`, (2)
  `node bench/validate.mjs`.
- `validate.mjs` reads only committed JSON (`bench/out/all/audit.json`, `bench/gold/labels.json`,
  `site/data.json`) and **recomputes** the headline "1 in N", per-agent board counts, receipt integrity
  (every published cite traces to a real audit verdict), and judge↔human κ. **No model, no network.** This
  is exactly the "keeps the leaderboard honest" merge gate.
- The tests (`stats`/`scoring`/`domains`/`agreement`) are pure functions over fixtures — no network.

**What CANNOT run in cloud CI (correctly documented in the workflow header):** a **fresh re-judge**. The
judge is a local Ollama `qwen2.5:14b-instruct` (or DeepSeek via `DEEPSEEK_API_KEY`). Cloud runners have
neither, so `npm run bench` (re-judging) is intentionally **not** a CI step. Re-judging happens on a machine
with a judge; CI only proves the *committed* receipts are internally consistent.

**Path-trigger edit needed after split:** the workflow triggers on
`paths: ['bench/**', 'site/**', 'package.json']`. After the split these paths are repo-root-relative and
**already correct** (no `doesitlie/` prefix). ✅ No path edit required — but **add `npm ci`** before the test
step (CI currently assumes no install because nothing imported external deps; after §5 vendoring, `bench`
will need `cheerio`/`pdfjs-dist` installed). Recommended job:
```yaml
- uses: actions/setup-node@v4
  with: { node-version: '20', cache: 'npm' }
- run: npm ci
- run: node --test bench/test/*.test.js
- run: node bench/validate.mjs
```
> Note: `validate.mjs` + the unit tests do not themselves import `cheerio`/`pdfjs` (those are only on the
> live-fetch path inside the verifier). So CI would pass even without `npm ci` **today** — but add it anyway
> so the repo is honestly installable and a future test that exercises the verifier doesn't silently break.

**Optional CI hardening (post-launch):** add a self-hosted runner with Ollama, **or** set `DEEPSEEK_API_KEY`
secret + a manual `workflow_dispatch` re-judge job (already hinted in the workflow header). Keep it
`workflow_dispatch`-only — a re-judge on every push would be slow, costable, and non-deterministic (unpinned
`deepseek-chat`).

## 5. Import-path fix — break the dependency on `qsearch/src` (the load-bearing work)

### 5a. The exact dependency chain (enumerated from source)

```
doesitlie/bench/harness.js      imports ./verifier.js  (verifyCitation, VERDICTS, judgeLabel)
doesitlie/bench/validate.mjs    imports ./verifier.js  (VERDICTS) + ./harness.js + ./stats.js
doesitlie/bench/agreement.js    imports ./stats.js     (internal — fine)
doesitlie/bench/verifier.js  ──►  export * from '../../src/verifier/index.js'        ❌ crosses repo
doesitlie/bench/fetch_content.js ─► export * from '../../src/verifier/fetch_content.js' ❌ crosses repo

qsearch/src/verifier/index.js          imports ./fetch_content.js  +  node:crypto, node:fs
qsearch/src/verifier/fetch_content.js  imports ../fetch/html.js     +  ../crawl/crawl4ai.js
qsearch/src/fetch/html.js              imports 'cheerio'            +  node:dns/promises, node:net
qsearch/src/crawl/crawl4ai.js          imports node:child_process, node:url, node:path, node:readline
                                       └─ spawns  src/crawl/crawl4ai_worker.py  (pip: crawl4ai==0.8.6)
qsearch/src/verifier/fetch_content.js  also dynamically imports 'pdfjs-dist/legacy/build/pdf.mjs'
```

So the standalone repo must vendor, transitively:
`src/verifier/index.js`, `src/verifier/fetch_content.js`, `src/fetch/html.js`, `src/crawl/crawl4ai.js`,
`src/crawl/crawl4ai_worker.py` — and **declare the deps `cheerio ^1.2.0` and `pdfjs-dist ^6.0.227`** (today
inherited from qsearch root `package.json`; doesitlie's own `package.json` has **no `dependencies` block at
all**). Python `crawl4ai==0.8.6` is an optional runtime dep only for the headless fallback (the worker prints
a clean error if not installed).

> Confirmed there are **no other** cross-repo references: the only `../../` lines in the whole tree are the
> two re-exports above plus `harness.js` walking `['.env.local','../.env.local','../../.env.local']` to load
> a dotenv — see §5d.

### 5b. How to break it — recommended: **vendor the module verbatim** (don't inline-flatten)

Preserve the file layout so the diff is trivial and qsearch stays the canonical upstream:

```
doesitlie/                         (new repo root)
  src/verifier/index.js            ← copy of qsearch/src/verifier/index.js, ONE edit (see below)
  src/verifier/fetch_content.js    ← copy, edit its two relative imports
  src/fetch/html.js                ← copy verbatim
  src/crawl/crawl4ai.js            ← copy verbatim
  src/crawl/crawl4ai_worker.py     ← copy verbatim
  bench/verifier.js                ← change re-export target to '../src/verifier/index.js'
  bench/fetch_content.js           ← change re-export target to '../src/verifier/fetch_content.js'
```

Edits required (mechanical, low-risk):
1. `bench/verifier.js`: `export * from '../../src/verifier/index.js'` → `'../src/verifier/index.js'`.
2. `bench/fetch_content.js`: `export * from '../../src/verifier/fetch_content.js'` → `'../src/verifier/fetch_content.js'`.
3. `src/verifier/fetch_content.js` (vendored copy): imports `'../fetch/html.js'` and `'../crawl/crawl4ai.js'`
   — these stay correct under the mirrored `src/` layout, **no edit needed**.
4. `src/verifier/index.js` (vendored copy): the default `CACHE_DIR` is `'doesitlie/bench/.cache'`
   (cwd-relative). In the standalone repo the cwd is the repo root and the path is now `bench/.cache`. **Edit
   the default to `'bench/.cache'`** (or set `DOESITLIE_CACHE_DIR=bench/.cache` in the npm scripts). If this
   is missed, a fresh run writes to a nonexistent `doesitlie/bench/.cache` subpath and silently misses the
   committed cache → reproducibility quietly breaks. **This is the highest-risk single edit in the split.**
5. Trim the now-stale doc comments in both vendored files that say "thin re-export kept for the qsearch
   module" so the public code doesn't reference a repo readers can't see.

**Alternative (inline-flatten into `bench/`)** — collapse all five files into `bench/verifier.js` +
`bench/fetch_content.js`. Rejected: larger, harder to diff against upstream, and loses the clean "one
verifier, mirrored layout" story. Vendoring is less error-prone.
