How a verdict is entered

For each (claim, cited URL) a deep-research agent produced:

1 — Fabricated check · mechanical

Fetch the URL. If it 404s, fails DNS, or isn't a real page → Fabricated. Reachable but unreadable (paywall, 403, a PDF we can't parse) → a coverage gap, scored neither way.

2 — Support check · auditable judge

Extract the source, rank the passages that touch the claim's specifics, and a judge rules whether they back it → Supported / Partial / Unsupported. The source excerpt and the judge's evidence quote are filed beside every verdict — open any row on the Leaderboard to read it.

Reproduce it

Open code, open data, a committed verdict cache — a re-run returns the same figures (each verdict is pinned; hosted model aliases drift). Case law is public, so ground truth is clean; v1 is deliberately narrow (Florida's fabricated-citation rule takes effect 15 June 2026). Breadth comes after the method survives scrutiny.

Related work

Citation quality in deep-research agents is measured in several places now. DRACO (Perplexity) and DeepResearch Bench (USTC) score agents on citation accuracy across general domains; Rao, Wong & Callison-Burch measure fabricated-URL rates at scale; LegalCiteBench probes citation recall in legal models. doesitlie is the narrower, complementary case: a neutral record — no vendor money, the maintainer's own tools off the board — where each verdict opens its receipt for hand re-checking, the judge asks whether the source supports the claim (not merely whether the URL resolves), and ground truth is public case law fetched live.
